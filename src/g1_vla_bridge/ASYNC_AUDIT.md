# Async 闭环审查（2026-09-14）

## 结论与证据边界

长延迟下，async 可能只执行预测尾部，随后断供；没有未来重叠时 EMA 完全不参与。
时间对齐正确不意味着闭环稳定。本轮没有启动机器人、解除急停或调用模型，不能确认
用户报告的振幅增长的唯一根因。旧节点日志缺少逐轮预测、下发目标与实测关节同步记录。

## 主要发现

1. **顿挫可在准时的30Hz回调下复现。** 真实节点回调配合假时钟：观测年龄0.2秒、
   处理延迟0.7秒、预测30点/30Hz，每轮只剩3个可发布目标，之后18拍无新目标。
   最长下发间隔633ms，所有响应的重叠数为零，且尚未触发1秒断供超时。
   这是确定性复现，不是此次真机运行的逐拍测量。
2. **连续供应的条件比单次推理小于1秒更严格。** 预测覆盖从观测T到T+H。
   单请求在途时，上一段撑到下一响应需 H >= A + L_current + L_next，
   A为观测年龄、L为采观测至响应的处理时长，另需合并开销和抖动余量。
   以A=0.2秒、L=0.7秒计算需要至少1.6秒，当前H=1秒。
   此前实测处理约0.63~0.78秒，与该风险相符，但不是本轮实时测量。
3. **EMA不保证下发连续。** 它只融合同一未来时刻的预测；首次和新尾部100%写入。
   断供后恢复可能直接切换到新预测尾部。降低execution_rate_hz不延长预测时间，
   调alpha不能平滑零重叠，增大hold_timeout只延长保持目标。
4. **跳过前缀不是完整的闭环延迟补偿。** 模型没有收到等待期间已执行动作的前缀约束。
   底层无新臂指令时仍追踪上一目标，并不冻结实测关节；收到尾部时实际状态可能偏离
   模型的预测依据。record动作标签是目标指令，不是物理必达状态。
5. **训练服务端契约未核实。** 工作区没有dataset/serve_batch消费代码，输出帧步长、
   动作首点时间偏移仍待核实，不能擅改action_rate_hz来拉长轨迹。
6. **运行中换任务不清旧预测。** 当前任务回调只改文字，在途旧任务响应仍可被接收，
   并与新任务结果融合。日志确有运行中换任务，但无法证明与振荡同步。
   本轮未改变任务切换行为；诊断时先stop再换任务。
7. **观测一致性仍有边界。** 公共T未强制每轮递增；在线滚动拟合会修订腕图时间；
   在线动态头部历史TF与旧静态头部导出不同。没有证据判定这些导致本次振荡。

## 离线稳定性反例

审查时使用真实TimedActions和合成反馈策略，初始偏差1cm：延迟0.1秒
时收敛，0.8秒时10秒末窗口峰值约47cm。慢响应时alpha=.01与1输出相同，重叠全为零。
合成策略不是CogACT，理想执行器也不是机器人，因此不能据此估计真机增益或振幅。
一次性合成实验已从测试集移除；常量预测不放大、融合计数归入test_timed_actions.py，
断供复现保留在test_async_execution.py。已有短弧旋转、过期不重放、generation隔离覆盖。

## 新增诊断

~/status新增async_merge（accepted/overlap/new及累计值、observation_to_response_s、
prediction_remaining_s、first_action_offset_s），计数单位是预测网格点，不是实际发布数。
async_target_step记录各臂原始目标相对上一发布目标的position_m/rotation_rad/gripper_rad，
在可选限幅之前计算，不是实测误差或物理速度。async_since_publish_s表示距上次发布时长。
停止保留最后诊断，下次start清零；停止后距上次发布时长仍增长。旧运行无法追溯这些值。

本轮只增加诊断与测试，没有调整控制策略、EMA、频率、限速或时间原点。
后续需同步记录完整响应、目标、limited_pose和实测关节：目标自身反向放大时查模型闭环
与时间契约；目标平稳而实测振荡时再查底层跟踪/IK。未验证并修复真机自激。
