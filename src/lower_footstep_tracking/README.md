# Lower Footstep Tracking

独立腿腰脚步任务，拥有 0–14 槽并直接交付掩码关节目标。TaskBase 提供传感器、任务注册和启停事件；本包持有站立过渡、足端 FK、冻结锚点调度与 78 维观测的 GRU 推理。默认模型为 `config/policy.onnx`，当前权重迭代号为 150351；模型仅接收左右脚下一落点 `L_next/R_next`，不再输入支撑脚落点；支撑脚记录仍供执行调度与停车保持使用。网页模式提供世界坐标脚步生成、队列管理和机器人控制。

模型契约版本为 `g1_footstep_gru_v5_next_only`，控制周期 0.02 s，输入为 `obs [1,78]` 与 `h_in [1,1,64]`，输出为 `actions [1,15]` 与 `h_out [1,1,64]`。观测前 72 维为关节、IMU、相位与步频，末尾六维为同一冻结锚点坐标系中的左右下一落点 `[dx,dy,dtheta]`。运行、增益导出和测试均读取 ONNX 内嵌契约。该模型尚未完成真机验证。

## 启动

```bash
ros2 launch lower_footstep_tracking footstep_tracking.launch.py
```

默认配置已提供六项 `foot_sole_offsets: [0.04, 0.0, -0.035, 0.04, 0.0, -0.035]`，顺序为左 xyz、右 xyz，单位米。可用 `config:=/path/to/calibrated_footstep.yaml` 叠加现场配置；`config` 支持本包配置名或绝对路径，参数采用 `/**: ros__parameters`。运行环境需已安装 onnxruntime 与 pinocchio。

### 腰部输出低通

默认对腰部目标启用一阶 Butterworth IIR 低通，抑制策略输出中的高频分量。2026-10-13 用户真机试用反馈效果良好，腰部抖动得到改善，现作为默认特性保留。

`waist_output_cutoff_hz` 默认 `10.0`，在策略目标发布前仅对 `waist_yaw_joint`、`waist_roll_joint`、`waist_pitch_joint` 的绝对位置目标滤波；50 Hz 更新率下，10 Hz 为 -3 dB 截止点，高频渐进衰减而非完全截断。启动时以实测腰角初始化，普通暂停/续走保留滤波历史；腿部目标、传感器反馈、模型输入和 GRU 更新不改，准备插值也不经过此滤波。

参数只在节点启动时读取，通过自定义 `config` 设为 `0.0` 可关闭，正值必须小于 25 Hz。修改后停止运动并重启脚步节点；滤波会引入相位滞后，调整截止频率后仍需现场验证。

### 足底参考点与标定

足底参考点对应训练 XML 的 `left_foot/right_foot` site，分别位于 `left_ankle_roll_link/right_ankle_roll_link` 下，不是踝关节原点、质心、COP 或动态接触点。2026-10-13 训练侧返回的冻结模型核对报告，用五组确定关节角和骨盆姿态对照本部署 URDF，确认上述局部偏移在 `1e-6 m / 1e-6 rad` 阈值内一致，不需要固定旋转补偿。实现使用完整 ankle 旋转计算 `p_site = p_ankle + R_ankle @ offset`，site yaw 可直接取 ankle yaw，不能用 yaw-only 旋转代替完整姿态。髋/膝固定旋转表示精度带来的纳米级残差不作为校准值。

该报告确认的是模型几何，不是硬件标定。`foot_encoder_offsets` 仍缺省为 29 个零；只有确认反馈角度零位、方向、弧度单位和速度方向一致后，才可采用该值。需要偏置时按模型 contract 的 29 关节顺序配置 `delta = q_training - q_feedback`，观测加 delta，动作目标减 delta；默认站姿的减法在模型内部，部署不重复减。正方向相反需统一映射反馈角、速度和输出，常量偏置不能修复。空列表不表示已标定，会被长度检查拒绝。IMU 轴系、在线四元数顺序及实际 `/robot_description` 仍需现场核对，不因模型比对通过而视为已确认。

## 网页工作台

```bash
colcon build --packages-select lower_footstep_tracking --symlink-install
source install/setup.bash
ros2 launch lower_footstep_tracking footstep_tracking.launch.py web:=true localization:=fused port:=8210
```

需叠加现场标定时，添加 `config:=/path/to/calibrated_footstep.yaml`；默认足底偏移不替代编码器或 IMU 现场标定。

打开 `http://localhost:8210`。需要已有 FPC、`g1_motion_session`、关节反馈、盆骨 IMU 和 robot_description；网页启动自身不会接管或行走。通过「接管预备」完成准备插值，「启动跟踪」开始零频率保持，再用「执行队列」显式起步。

硬件控制栈需先提供 `/joint_states`、`/pelvis_imu_broadcaster/imu`、`/robot_description` 和 FPC。如果没有运行中的 session，可在另一个终端执行 `ros2 launch g1_motion_session session.launch.py`；已有 session 时不要重复启动。不要同时启动另一个下肢速度/脚步任务，或独占全身控制的 RGMT、回放等发布器。默认 fused 还需要有效的 `/dog_odom` 和已初始化的 `/g1_localization/torso_pose`；没有雷达时用 `localization:=planned`，此时没有实测全局位置反馈。

启动节点和打开网页不代表可以安全行走。执行前仍需确认反馈零位与方向、IMU 安装轴系、实际模型和保护条件；模型尚未完成真机闭环验证，连续 90° 转角也没有真机验证。

- 四向按钮从支撑脚生成「另一脚迈出、原支撑脚并齐」两步，不再把当前两脚的前后错位或过宽站姿一起平移。空队列使用相位调度记录的支撑侧，不通过接触检测选择；已有队列则从尾部双脚和下一异侧脚接续，左右按钮也不强制固定某只脚先迈。位移方向始终取点击时的实时躯干航向，不取两脚脚尖 yaw 的平均值或队列末端 yaw。先迈脚目标为支撑脚位置加躯干方向位移，再加沿支撑脚朝向的左右间距；原支撑脚随后按先迈脚的朝向并齐，间距使用页面站距值。首次起步前目标脚印沿躯干航向；行走后分别保留两脚已有计划 yaw，不因躯干与计划航向偏离而隐含转向。超界时尝试拆成多轮小步，不截断输入的方向位移；已有错位站姿会在并脚时重新对齐，因此不是两只脚各自原位置加同一向量。原地转向仍添加两脚旋转目标，空队列的目标 yaw 是躯干 yaw 加输入转角；连续追加保留累计转向。它们都追加到连续队列，不是单脚训练动作。
- 「站定」追加一个下一脚并齐落点，以队列末端的另一只脚为支撑，前后位置和 yaw 对齐、横向间距使用页面的站距值；没有既有计划时以当前脚位为基准。按钮不清空队列、不自动起步，仍通过「执行队列」运行。作为队列末尾执行时，自动收脚保留该显式间距，不再强制改为 0.24 m。
- 路线按鼠标或触摸的绘制顺序采样，松开后立即显示左右交替脚印草稿；修改采样间距、站距或朝向选项会重新预览。「朝向跟随路线」表示尽量跟随路线，不要求脚印立即对齐折线切线：生成器按实际落点可行性减小每步转角，允许脚印朝向滞后、侧移跟进；两脚偏移按最终脚印朝向布置。预览与正式入队都校验生成后的脚印，不对折线夹角另设上限；无法生成满足站距、步长和转角约束的脚印时显示原因并禁用提交。预览不改变执行队列，点击「加入队列」才追加脚步，提交后保持世界坐标不变。
- 脚步模式按下确定落点，同次拖动确定朝向，松开完成一个左右交替脚步；不拖动时沿当前视图前向。新建脚印移动不足 6 像素时保持初始 yaw，避免点击抖动意外转脚；超过死区后按拖动方向定向。已有草稿拖脚印改 XY，拖朝向柄改 yaw；下方数值框使用世界坐标。待执行队列可复制为草稿编辑，已承诺落点不可修改。待执行队列、尾部计划双脚或下一脚改变后，旧草稿将被拒绝，需重新编辑；待执行队列为空时自动追加收脚也会使旧预览失效，单纯消费承诺头步而不改变尾部规划基准则不会。
- 视图以躯干为基准，躯干前向 +X 始终朝屏幕上方，左向 +Y 朝屏幕左方；深色箭头表示躯干前向，脚印允许有不同偏角。编辑期间冻结视图位置，但航向始终跟随躯干；草稿和已提交落点保留世界坐标，不随视图转动改写。彩色当前足印来自 URDF + 编码器 + IMU 的 FK，不是 IK；灰色虚线足印显示调度器保存的计划站姿，队列从该站姿及已承诺、待执行落点接续，不能把 FK 当前脚位误作计划起点。
- 步频表示完整左右周期/秒。连续执行采用 0.5 s 起步、巡航 0.2 Hz/s 频率变化限速，保持四个已承诺落点；队列耗尽或「暂停行走」保留承诺并追加另一脚收步，终态前后对齐、默认间距 0.24 m；末尾已有显式站定落点时保留其间距，另一脚保持原位，末尾 0.5 s 降频。暂停后保留相位和 GRU，等待显式继续，收脚中不取消停止。
- 「停止任务」与「急停」使用 session 原有停止接口，不执行脚步收步，FPC 保持最后关节目标。「急停」点击立即发送请求，没有确认弹窗，也不被普通命令的等待状态阻挡。「暂停行走」才是策略内正常停车。浏览器状态轮询中断超过 `footstep_browser_timeout_s`（默认 2 s）请求正常暂停；这不是硬件急停。

### 定位与调度

默认 `localization:=fused`，复用 `g1_rgmt_tracking_global.OdometryFuser`，融合 `/dog_odom` 与 `/g1_localization/torso_pose`；局部里程计先通过本任务的 URDF 腰部 FK 从盆骨归算到躯干。再用融合世界位置与同一世界修正后的 IMU 姿态计算足底 XY/yaw，将左右最近目标共同表达在冻结支撑参考系中。雷达需已设置定位原点，负协方差的未初始化帧被忽略；定位超时报告故障，不静默降级。任务运行中不得重设外部定位世界原点，否则既有世界脚印失去坐标语义。

没有雷达时选择 `localization:=planned`，或在未接管/已停止状态切换页面定位选项。这时把上一计划落点当作已踩到位的支撑位置，依次转换相邻目标，并显示「无全局位置反馈」；UI 当前足印是计划锚点结合 FK 的估计，不代表实测世界轨迹。不存在独立的定位纠偏或滑移检测，也不在脚印之间额外创造轨迹目标。

跨越理论落地相位时消费目标并重建参考系：planned 使用计划落点，fused 使用当拍 FK 脚位。脚步按相位推进，不因模型落地偏晚或未通过 FK 接触判据而终止；启动不等待双接触，收脚降频结束后直接进入保持。站立冻结参考系，持续传感器读取与 GRU 推理；页面保持计时是调度状态时长，不代表实测接触或稳定性。没有足底力反馈时，调度不会判断真实脚是否已经触地。

### 使用边界

页面站距表示两脚足底参考点的横向间距，不是鞋底内侧净空，默认 0.24 m。当前策略默认关节角或全零关节角配合本部署模型、默认足底偏移和零编码器偏置，离线 FK 横向间距均约为 0.2370 m；原先零足底偏移和两侧 `(0, 0, -0.035)` m 示例偏移也得到该横向值，不能只凭脚距确认足部坐标。这不是实际机器人测量，真机脚位由反馈关节角和标定足底偏移计算。若测得 12 cm，需区分鞋底内侧净空与参考点间距，不能据此自动把默认站距减半。

时序依据工作区 `about_footstep_in.md`。队列强制左右交替、正确侧关系、连续站距 0.12–0.36 m、相邻平面位移不超过 0.48 m；连续队列只限制相邻异侧脚印的 yaw 变化不超过 90°，不限制相对接管时初始航向的累计转角。首步同样相对当前支撑脚校验；路线转弯允许脚印朝向滞后，并不强制按轨迹切线立刻转身。自定义或方向动作的超界脚印整批拒绝，不静默截断。方向动作的横向位移叠加在指定脚间距上；例如站距 0.24 m 且脚尖与躯干同向时，单步向外最多 0.12 m、向内最多 0.12 m，先迈哪只脚由支撑侧和队列交替顺序决定。四向按钮会自动尝试更小的位移分段，各步仍须通过原几何校验；无法分段生成合法计划时仍整批拒绝，错误侧关系不会取绝对值放行。

网页首次起步前，未落地初始支撑脚的横向站距使用准备时的躯干航向检查，避免脚尖偏角导致合理斜步被误判过近或跨脚；进入计划后沿落地脚步的航向检查。真实 FK 脚姿态、观测和冻结支撑锚点不作此替换，脚 yaw 限制也仍按真实/计划姿态检查。站距拒绝提示包含步号、左右脚及算得的实际横向间距，不能仅凭脚印外观确认可执行性。

站距是沿支撑脚朝向计算的有符号横向分量，不是两脚中心的直线距离；负值表示目标位于该支撑朝向所认定的错误侧。例如先绘制右脚、再绘制左脚时，第二步按第一步右脚的 yaw 检查左右关系；右脚意外转到 90° 时，画面上接近的下一左脚仍可能被算成负站距。绘制时应同时核对左右标签、脚印箭头和计划站姿。

单脚训练分支仍保留相邻与相对初始航向 ±30° 的限制；网页的方向按钮与路线均使用连续队列。连续队列采用相邻 90°、不限累计航向是部署侧的任务要求，不改变训练文档的 30° 分布记录；大单步或累计转弯的策略表现尚未经过真机验证，几何约束通过不等于策略或硬件必能完成。

当前没有地形、障碍物、双脚碰撞或外部足底接触验证；该模型仍未完成真机验证。HTTP 服务没有登录鉴权，默认监听 `0.0.0.0`，只应暴露在可信机器人网络/本机端口转发中，可将 `footstep_web_host` 设为 `127.0.0.1`。跨域 JSON 命令被拒绝，但这不能替代网络访问控制。Lucide 固定版本资源随包安装，运行时不请求 CDN。

## 接口

非网页模式保留计划入口 `/motion_control/lower/input/<lower_source>/footsteps`，默认来源 `planner`，消息类型为 `lower_footstep_tracking/msg/FootstepPlan`，定义位于本包 [msg/FootstepPlan.msg](msg/FootstepPlan.msg)。该旧入口保留原始步频设置与停车行为，不包含网页队列的完整起停规划；网页模式不订阅它，避免与世界脚步队列竞争。常规换锚不清 GRU。

`/robot_description` 绑定成功后 `ready` 为真。engage 由基类执行两段准备插值，终点发布后由 FPC 保持，等待显式 start 初始化 FK 锚点与 GRU；stop 停止本任务输出，FPC 保持最后目标。`status()` 提供原 lower 字段与嵌套 `footstep` 字段。

## 导出

```bash
ros2 run lower_footstep_tracking export_policy_gains --model /path/to/model.onnx --output /tmp/footstep_gains.yaml
```

导出工具读取模型内嵌契约，只覆盖公共 PD 配置中策略拥有的腿腰增益；输出文件由操作者另行选择加载。
